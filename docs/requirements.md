# Requirements

Status: Draft

No product requirements are confirmed yet.

## Functional requirements

To be defined after the product brief establishes the problem and target user.

## Non-functional requirements

To be defined after platform, privacy, accessibility, performance, and
operational constraints are understood.

## Requirement format

Each requirement should include:

- Identifier
- Status: proposed, confirmed, deferred, or rejected
- User need and expected behavior
- Acceptance criteria
- Dependencies or constraints
- Source or decision reference
